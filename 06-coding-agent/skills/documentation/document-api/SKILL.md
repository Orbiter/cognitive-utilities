# Document API

## Purpose

Document an API accurately enough for another developer to integrate without reading the implementation.

## Procedure

1. Identify endpoints or public functions and their stability boundary.
2. Document inputs, outputs, defaults, error cases and side effects.
3. Include a minimal valid example.
4. Include authentication, rate or lifecycle constraints where relevant.
5. Distinguish required from optional fields.
6. Verify examples against current code or schema.

## Completion criteria

- The requested outcome is implemented or the investigation is concluded.
- Relevant evidence is inspected rather than guessed.
- Any changes are checked for obvious regressions.
- Remaining uncertainty or risk is stated explicitly.
